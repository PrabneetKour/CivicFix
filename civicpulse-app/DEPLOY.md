# Deploying CivicFix

Three services, all free to start: **Render** runs the API and PostgreSQL, **Cloudinary**
holds the photos and video, **Vercel** serves the client.

Allow about two hours the first time, most of it waiting on builds.

---

## 1. Cloudinary — 10 minutes

Photos currently write to `server/uploads`. Render wipes its filesystem on every restart
and every deploy, so without this, every photo residents have filed disappears the first
time the service sleeps. This is not optional.

1. Sign up at cloudinary.com — the free tier is 25 GB, far more than this needs
2. On the dashboard find **API Environment variable**
3. Copy it. It looks like `cloudinary://123456789:abcdefg@your-cloud-name`

Keep it somewhere for step 2. Treat it as a password — it is one.

---

## 2. Render — 30 minutes

### The blueprint

1. Push this repository to GitHub if you have not already
2. Render dashboard → **New** → **Blueprint**
3. Select the repo. Render reads `render.yaml` and offers to create `civicfix-api` and
   `civicfix-db` together
4. Apply

The database is created and wired to the API automatically. `JWT_SECRET` is generated by
Render. Four values it cannot know are left blank, and the service will not start until
they are set.

### The four secrets

**civicfix-api → Environment**, add:

| Key | Value |
|---|---|
| `CLOUDINARY_URL` | from step 1 |
| `ADMIN_PASSWORD` | pick something real — not `admin123` |
| `CLIENT_ORIGIN` | leave blank for now, filled in at step 3 |
| `GOOGLE_CLIENT_ID` | your client ID, or leave blank to hide the button |

Save. Render redeploys.

### Create the tables

The database is empty until the schema runs. Render dashboard → civicfix-api → **Shell**:

    npm run setup

You want "Tables, indexes and triggers are in place" and "Admin ready". That also creates
the admin account from `ADMIN_EMAIL` and `ADMIN_PASSWORD`.

Then check `https://civicfix-api.onrender.com/api/health` returns `{"ok":true}`. Note that
URL — the client needs it next.

---

## 3. Vercel — 15 minutes

1. vercel.com → **Add New** → **Project** → import the repo
2. **Root Directory**: `civicpulse-app/client-ui`
3. Framework preset: Vite. Build and output settings are detected correctly
4. **Environment Variables**:

| Key | Value |
|---|---|
| `VITE_API_URL` | `https://civicfix-api.onrender.com` — no trailing slash |
| `VITE_GOOGLE_CLIENT_ID` | your client ID, if using Google |

5. Deploy

Vercel gives you something like `https://civicfix.vercel.app`.

---

## 4. Close the loop — 5 minutes

**Back on Render**, set `CLIENT_ORIGIN` to the Vercel URL and save. Until this is done the
API refuses the browser's requests, because CORS is locked to a named origin rather than
open to the internet.

**In Google Cloud Console** → Clients → your OAuth client → **Authorised JavaScript
origins**, add the Vercel URL. This is the last time you have to touch it: unlike a tunnel,
this address never changes.

---

## What you get

A permanent HTTPS address. GPS works on any phone with no tunnel, no certificate warning,
no firewall rule. The app installs to the home screen properly. Anyone can open it without
your laptop being on.

---

## The free tier's one real drawback

Render's free instances sleep after 15 minutes idle, and the next request takes 30 to 50
seconds while it wakes. Fine for showing someone, poor for a live demo unless you open the
URL a minute beforehand.

$7 a month removes it. Free cron pingers that hit `/api/health` every 10 minutes also work,
though Render discourages it.

The free database is dropped after 90 days. Take a dump before then if the data matters:

    pg_dump "$DATABASE_URL" > backup.sql

---

## When something is wrong

**"Failed to fetch" in the browser.** `CLIENT_ORIGIN` is unset or does not exactly match
the Vercel URL, or `VITE_API_URL` has a trailing slash. Check the browser console — a CORS
rejection says so explicitly.

**Photos upload but never appear.** `CLOUDINARY_URL` is not set, so the server wrote to a
disk that no longer exists. The server logs which storage it chose on every boot.

**The API will not start.** Render logs → look for the missing variable. The server exits
deliberately when `DATABASE_URL` or `JWT_SECRET` is absent, rather than failing mysteriously
later.

**Sign-in works, everything else 401s.** The client is calling the wrong origin. Check
`VITE_API_URL` and remember Vercel needs a redeploy after an environment change — it bakes
these into the build.

## Then: the native app

With the backend deployed, Capacitor can wrap the client into an installable APK:

    cd client-ui
    npm install @capacitor/core @capacitor/cli @capacitor/android @capacitor/camera @capacitor/geolocation
    npx cap init CivicFix com.civicfix.app
    npm run build && npx cap add android && npx cap sync
    npx cap open android

Then swap the report form's file input for the native camera. That is the fix for the EXIF
problem: the app captures the photo and reads the GPS chip itself, at the same moment, so
the coordinate never passes through a file anyone could edit. `REQUIRE_GEOTAG` becomes
meaningful again.

Needs Android Studio and a JDK — several gigabytes and an unhurried afternoon.
